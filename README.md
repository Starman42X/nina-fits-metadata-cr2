# FITS Metadata for CR2 – N.I.N.A. plugin

When N.I.N.A. saves DSLR frames in the camera's native raw format, the file only holds what the camera
knows: exposure, ISO, date. Everything N.I.N.A. knows about the frame (target and coordinates, image type,
site, telescope, filter, focuser, sensor temperature, rotator, weather, headers from other plugins) normally
only ends up in FITS/XISF files.

This plugin writes those FITS keywords into every saved Canon CR2 file as XMP metadata.

## What gets written

- **Every keyword N.I.N.A. would put into the FITS header**, generated by N.I.N.A.'s own FITS header code so
  they match a FITS file exactly. Each one becomes an XMP property with the prefix `fits`:
  `fits:OBJECT`, `fits:IMAGETYP`, `fits:RA`, `fits:DEC`, `fits:FILTER`, `fits:FOCALLEN`, `fits:SITELAT`,
  `fits:FOCPOS`, `fits:CCD-TEMP`, ... Keywords added by other plugins are included.
  Only the keywords that describe the FITS data array itself (`SIMPLE`, `BITPIX`, `NAXIS*`, `BZERO`, ...) are left out.
- **The target name** as the image title (`dc:title`)
- **The site** as standard GPS coordinates (`exif:GPSLatitude`, `GPSLongitude`, `GPSAltitude`)

The two standard fields mean photo tools (Lightroom, Bridge, digiKam, ...) show the target and location too.

Read the FITS keywords with [ExifTool](https://exiftool.org/):

```
exiftool -XMP-fits:all IMG_0001.CR2
```

## The raw data is never touched

Canon reserves 8 KB inside every CR2 for XMP metadata (that's where the in-camera star rating lives).
The plugin writes into that space, so the file size stays the same and only bytes inside that block change.
Existing XMP such as the rating is kept, and writing again replaces the plugin's own properties rather
than adding duplicates.

If the metadata does not fit, it is appended to the end of the file together with a copy of the first
image directory. No existing byte is moved. The file header is switched to the new directory last, so an
interrupted write leaves the original file readable.

Tested with a Canon EOS 2000D CR2: dcraw/LibRaw decode bit-identical raw data before and after, and read the
same camera information.

Other TIFF-based raw formats (NEF, ARW, DNG, PEF) are handled the same way, but have not been tested.
CR3 is not TIFF-based and cannot be written into. Use the sidecar option for it.

## Requirements

- N.I.N.A. 3.2 or newer (64-bit)
- *Options → Imaging → File format* set to **RAW**, otherwise N.I.N.A. saves FITS/XISF/TIFF and there is
  no CR2 to write into. The plugin's options page warns when this is not set.

## Install

1. Close N.I.N.A.
2. Unzip so that the folder `FITS Metadata for CR2` ends up in `%LOCALAPPDATA%\NINA\Plugins\3.0.0\`
3. Start N.I.N.A. The plugin is listed under *Options → Plugins*.

## Options

| Option | Default | |
|---|---|---|
| Write FITS metadata into the raw file | on | |
| Also write an .xmp sidecar file | off | `IMG_0001.CR2` gets `IMG_0001.xmp` next to it (Lightroom's naming). Existing sidecar content is kept |

The options page also shows the last file that was processed. Problems are logged in the N.I.N.A. log
and shown as a notification.

## Build

```
dotnet build FitsMetadataForCr2 -c Release
```

Requires the .NET 8 SDK. Ship only `NINA.Plugin.FitsMetadataForCr2.dll` from the build output.
Everything else is provided by N.I.N.A.
